# Fact-RNDC-Alt

Web app for Colombian electronic freight invoicing (DIAN UBL 2.1) and RNDC
(Ministerio de Transporte) integration. Rewrite of the original FE-Tool
(Python/Streamlit) as a React + Express + Postgres app, deployed on
**Vercel** (hosting) and **Supabase** (Postgres database).

## Profiles are dynamic

Unlike the original app, this one is **not** hardcoded to any specific
companies. A "perfil" is a company profile — its RNDC credentials, NIT, and
a real sample invoice XML — created and managed entirely from within the
app (Perfiles section, admin-only). Add as many as you need; there's no
fixed set of profiles baked into the code.

Each perfil needs a **real, already-valid invoice XML** uploaded as its
template. New invoices are generated by editing that template's header
fields and remesa lines in place (`backend/src/services/xml/templateEditor.ts`)
— everything else (digital signature, certificate, DIAN authorization,
supplier address) is preserved exactly as it was in that template, since
it's a real document DIAN/RNDC already accepted for that company.

## Stack

- **Frontend**: React 18, TypeScript, Vite, Tailwind, Zustand, React Router,
  Lucide, Recharts, React-Leaflet
- **Backend**: Node.js, Express, TypeScript, `pg` (raw SQL, typed query
  modules, no ORM), Zod
- **Auth**: JWT issued by the backend, roles `admin` / `operador`
- **Database**: Postgres via Supabase (pooled/pgbouncer connection)
- **Deployment**: one Vercel project — the Express app is exported as a
  serverless function (`api/index.ts`), the frontend builds to a static SPA

## Monorepo layout

```
frontend/        React app
backend/         Express API
shared/          Zod schemas + types shared by both
api/index.ts     Vercel serverless entrypoint
vercel.json      routes /api/* to the function, everything else to the SPA
```

## Local development

Requirements: Node 20+, a Supabase (or any Postgres) database.

```bash
npm install

cp .env.example backend/.env
# fill in DATABASE_URL (Supabase pooled connection string), JWT_SECRET,
# CREDENTIALS_ENC_KEY (openssl rand -hex 32 for the last two)

npm run migrate --workspace=backend
npm run seed:admin --workspace=backend -- admin@example.com "yourPassword123"

npm run dev:backend    # http://localhost:4000
npm run dev:frontend   # http://localhost:5173 (proxies /api to the backend)
```

Run tests: `npm test` (backend unit tests — number parsing, XML template
editing).

## Deployment

Push to the Vercel project connected to this repo. Set the same three
environment variables (`DATABASE_URL`, `JWT_SECRET`, `CREDENTIALS_ENC_KEY`)
in the Vercel project settings, then run the migration once against the
production database (`npm run migrate --workspace=backend` with production
`DATABASE_URL`) and seed the first admin.
